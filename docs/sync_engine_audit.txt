الملفات والدوال بالترتيب الزمني:

  ① الكتابة المحلية   lib/data/repository.dart
                       saveTx() (~سطر 651) — داخل db.transaction ذرية.
  ② تسجيل العملية     lib/data/sync/recorder.dart
                       SyncRecorder.record() (سطر 59).
  ③ التحفيز الفوري    lib/data/sync/sync_engine.dart

التدفق:
  saveTx يكتب في transactions ويستدعي newRecorder(txn) داخل نفس المعاملة
  ← record() يُدرج صفاً في operations (لقطة كاملة للكيان) + صفاً في
  sync_queue لكل هدف ← الـ callback الثابت SyncRecorder.onOperationRecorded
  (مربوط في SyncEngine.start) يفجّر الدفع الفوري.

المستمع — ليس onChildAdded (لا Firebase SDK؛ REST خالص):

التطبيق المحلي — لا upsert أعمى ولا SQL خام مباشر:
  lib/data/sync/apply_remote.dart ← applyRemoteOperation(txn, op, resolver):
  1. Idempotency: op.id موجود في operations؟ ← تجاهل (سطر 30).
  2. فحص وجود الكيان + آخر نسخة محلية ← قرار الـ resolver.
  3. التطبيق مفلتر بالمخطط: PRAGMA table_info ثم بناء صف من الأعمدة
     الموجودة فعلاً ← txn.update إن وُجد الصف، أو txn.insert مع إكمال
     أعمدة NOT NULL الناقصة بقيم آمنة (سطور 125-160).
  الكل داخل معاملة واحدة (خصائص ACID محفوظة).

حسم التعارضات — lib/data/sync/conflict_resolver.dart (سطور 18-75):
  سلّم حسم حتمي يعطي نفس النتيجة على كل الأجهزة:
  1. incoming.version > localVersion  ← طبّق.  أقل ← تجاهل.
  2. تعادل النسخ:
     - نفس الجهاز ← طبّق (تكرار آمن).
     - وإلا: timestamp الأحدث يفوز.
     - تعادل تام: deviceId الأصغر معجمياً يفوز (ثابت عبر الأجهزة).
  3. حالة غامضة ← صف notifications «تعارض في المزامنة» + حفظ العملية
     دون تطبيق.

  ملاحظة: server_ts ليس للحسم — هو مؤشر السحب فقط:
  pull() يقرأ lastCloudTs:$wsId من sync_meta ويرشّح
  orderBy="server_ts"&startAt= مع تداخل ثانيتين، مع تراجع تلقائي
  لجلب كامل + فرز محلي عند غياب ".indexOn" (سطور 191-201).

مشغّل بانر الخطر — sync_engine.dart: _checkDangerState() (~سطر 257):

  SELECT COUNT(DISTINCT q.operation_id) c,
         MIN(q.created_at) oldest, MAX(q.attempts) att
  FROM sync_queue q JOIN operations o ON o.id = q.operation_id
  WHERE q.status IN ('pending','failed','syncing')
    AND o.entity_type NOT IN ('message','conversation')

  - العدّ بعمليات مميّزة (لا صفوف طابور) — هدفا lan+cloud لنفس
    العملية لا يضاعفان العدد (إصلاح دفعة 49).

  - وضع standalone ← صافٍ دائماً.
  - يُفحص كل 8 ثوانٍ + فور نهاية كل processQueue إن كان البانر ظاهراً.

العمليات المنطقية — lib/data/sync/sync_queue.dart (SyncQueueOps):
  pickPending()    يرتّب attempts ASC (منع تجويع العمليات الجديدة
                   خلف طابور قديم عالق).
  markFailed()     لا فشل نهائي إطلاقاً — دائماً يعود pending مع
                   backoff: 5ث ← 10 ← 20 ← 45 ← 60ث ثم سقف دقيقتين
                   للأبد حتى تنجح.
  retryFailed()    تصفير كامل (يدوي) — الحالة والمحاولات والمواعيد.
  resumeBackoff()  تصفير next_try_at فقط (عودة الاتصال) — دفعة 49.
