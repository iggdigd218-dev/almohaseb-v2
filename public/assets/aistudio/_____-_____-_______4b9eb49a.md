# ٢) العلل الحرجة الجديدة 🔴 (1)

### NC1 — قناة نشر التحديث إلى القاعدة مكسورة بصمت (تحديث التطبيقات مجمّد)
- **الموضع:** `.github/workflows/build-flutter-apk.yml` الأسطر 153-156 (+ **7 طلبات نشر مماثلة بلا مصادقة** في بقية الـworkflows): أربعة `curl PUT/PATCH` إلى `…firebasedatabase.app/system/version_manifest.json` و`force_update.json` ومسار `_registry` القديم — **بلا أي `?auth=`** وتُختم كلها بـ`|| true` (ابتلاع الفشل).
- **الخلل:** القواعد المقسّاة الجديدة تجعل كتابة `/system` **للمشرف حصريًا** → كل عمليات النشر تُرفض بـ401 **بصمت**، فيبقى البيان المنشور مجمّدًا على آخر إصدار قُبل قبل التقسية. والطامة المكتملة: `/system/version_manifest` قراءته **عامة** (تنجح وتعيد البيان القديم)، لذا فشلَ قراءة القاعدة لا يحدث أبدًا و**لا يتفعل الاحتياطي** (`kFallbackManifestUrl` على GitHub — update_service.dart:204-206 لا يعمل إلا عند فشل القراءة نفسها) → **العملاء لن يرون أي إصدار جديد أبدًا** عبر القناة الرسمية.
- **التصحيح المنطقي:** توليد idToken مشرف داخل CI (refresh token في GitHub Secrets — لا في الكود) وإلحاقه `?auth=` بكل curl، أو إسقاط النشر إلى القاعدة وجعل التطبيق يقدّم رابط GitHub مباشرة مع إزالة `|| true` ليصرخ الفشل بدل أن يُبتلع.
