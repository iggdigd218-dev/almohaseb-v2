# 🔑 مدير التراخيص — License Admin (Nexora)

تطبيق مستقل لمالك النظام فقط: تفعيل وترقية اشتراكات عملاء «مدير الحسابات»
مباشرة في نفس قاعدة Firebase RTDB دون أي تعديل يدوي.

## المزايا
- 📊 بطاقات إحصائية حية فور الفتح: إجمالي المساحات / مدفوعون / تجربة / منتهية.
- ✅ تفعيل بنقرة: ألصق بصمة الجهاز (من رسالة واتساب) أو معرف المساحة، اختر
  الخطة (فردي/مؤسسة) والمدة (شهر/3 أشهر/سنة/دائم) وسعة الأجهزة.
- 🕒 كل الحسابات بساعة خادم فيربيس حصراً (server_ts + المدة) — لا ساعة الهاتف.
- 📜 سجل المشتركين: آخر التفعيلات وحالتها الحية وزر «تمديد بنقرة» يبني فوق
  المدة المتبقية.

## 🆕 إصلاحات 1.1.0 (2026-09-22) — لماذا كان التطبيق «لا يعمل»
1. **الهوية الإلزامية**: قواعد RTDB تشترط `auth != null` على كل عقدة تلمسها
   اللوحة، فكانت كل قراءة/كتابة تُرفض بـ 401. الآن يُنشئ التطبيق هوية
   مجهولة تلقائياً (Firebase Auth) ويُجدّدها، ويرفق `?auth=` بكل طلب.
2. **الرابط الرسمي مضمّن**: كان فارغاً فتحتاج إعداداً يدوياً — الآن يعمل
   فور التثبيت، مع إمكانية التجاوز من ⚙️.
3. **سجل التفعيلات**: كان يُكتب في `/admin` المحجوبة بالقواعد فيُسقط
   التفعيل بعد نجاح الاشتراك — صار داخل `workspaces/<ws>/admin_log`.
4. **حسم المساحة المكررة**: جهاز يظهر في أكثر من مساحة عمل كان يُحلّ
   لأول مطابقة (مساحة ميتة) فيبدو الترخيص كأنه لا يُفعّل. الآن يُرجَّح
   الأحدث نشاطاً (`last_sync_at`) ثم الأكمل خطة، وإن تعذّر الحسم يُبلغك
   بالمرشحين لتختار.

## 🛠️ مراجعة وإصلاح 1.1.0+3 (2026-09-23) — جودة مدير الترخيص
1. **مشترك يختفي من السجل**: تعبير `max_devices` كان يقرأ أولوية العوامل
   خطأ؛ مساحة خُزّنت أرقامها كنصوص ترفع استثناءً يُبتلع داخل `try/catch`
   فيختفي المشترك من القائمة تماماً. الآن تحويل موحّد (`asInt`/`asMs`)
   يقبل رقماً أو نصاً — ويقرأ الحالة الحية قبل السجل.
2. **بطء البحث عن جهاز**: مسح متسلسل (طلب HTTP لكل مساحة، ومفاتيح
   المساحات تُطلب مرتين) كان يستغرق عشرات الثواني فيبدو التفعيل معلّقاً.
   الآن طلب واحد للمفاتيح + مسح بتوازٍ محدود (6) وبسقف 40 مساحة.
3. **حلقة هوية**: رمز تحديث تالف كان يدور (401 ⇒ تحديث ⇒ فشل ⇒ 401)؛ الآن
   يُسقط الرمز التالف ويبني هوية مجهولة جديدة فوراً.
4. **ساعة الخادم**: قياس واحد يُخزّن 45 ثانية ويُسند بساعة أحادية — بدل
   طلبين لكل عملية. وحالة «منتهٍ» في السجل صارت بساعة الخادم لا ساعة
   الهاتف (كانت ساعة هاتف مضبوطة خطأً تعكس الحالة).
5. **قائمة قديمة بعد التفعيل**: السجل كان يُحمَّل مرة عند الإقلاع؛ الآن كل
   تفعيل/تمديد يُحدّث السجل والبطاقات فوراً.
6. **ضبط واستخدام**: إفلات المتحكمات، نسخ المعرّفات بنقرة، بحث في السجل،
   توضيح «مساحات بلا اشتراك»، حد أدنى لسعة المؤسسة (2)، وتحذير عند إدخال
   فارغ قبل أي طلب شبكة.
7. **تحليل ثابت نظيف**: `flutter analyze` ⇒ 0 ملاحظات (كان 4)، و11 اختباراً
   جديداً (`test/qa_license_manager_test.dart`) تمرّ على التنفيذ الحقيقي
   لا على نسخة منطقية مكرّرة.

## 🔐 تأمين الترخيص (قيد التنفيذ — يحتاج خطوة واحدة من المالك)
قاعدة البيانات كانت مفتوحة الكتابة للعالم: أي شخص يعرف الرابط يستطيع كتابة
`status: active` على مساحته ويحصل على التطبيق المدفوع مجاناً (مُجرّب فعلياً).

الرقعة الجاهزة في `rules.license-hardened.json` تقفل **عقدتَي الترخيص فقط**
(`workspaces/$ws/subscription` و`workspaces/$ws/admin_log`) على هوية مدير
ثابتة — بقاعدة `.validate` لا `.write`:
- `_لماذا .validate؟_` قواعد فيربيس تتوارث من الأعلى للأسفل: أي `.write`
  أعمق تُتجاهل إذا كان الجذر يمنح `.write: true` (وهو حال القاعدة اليوم).
  أما `.validate` فلا تتوارث ويجب أن تتحقق في كل مستوى ⇒ تقيد بلا أثر على
  بقية العقد (المزامنة، الأجهزة، الطلبات، الفهرس) — صفر انكسار.
- التطبيق العميل يستطيع إنشاء/إصلاح/ترقية عقدة `subscription` بحالة `trial`
  وبمدة ≤ 30 يوماً من `created_at` (لا يستطيع منح نفسه `active`).
- المدير وحده (UID مضمّن في الملف) يكتب `status: active` والتمديد.
- تنبيه: بعد النشر، لوحة المدير بالإصدارات ≤ 1.1.0+3 تفقد حق الكتابة
  (هوية مجهولة) — ثبّت 1.1.0+4 وألصق رمز هوية المدير.

طريقة التطبيق (أي واحدة):
1. Firebase Console ← Realtime Database ← القواعد ← الصق محتوى الملف ← انشر.
2. أو أعطِ مادة قاعدة البيانات (Database secret) أو توكن OAuth وسيُطبَّق
   تلقائياً عبر `curl`.

بعد النشر: ثبّت هذا الإصدار وألصق «رمز هوية المدير» مرة واحدة من ⚙️
(يُحفظ على هاتفك فقط) — وبدونه يعمل التطبيق قراءةً فقط.

## خطوات التشغيل
1. ثبّت `license-admin.apk` (يبنيه CI تلقائياً) على هاتفك فقط — لا يوزَّع للعملاء.
   - **مرة واحدة فقط**: إن كان مثبتاً إصدار قديم (≤ 1.1.0+4) فاحذفه أولاً ثم
     ثبّت هذا الإصدار — تلك النسخ كانت تُوقَّع بمفتاح debug يتغيّر كل بناء،
     وأندرويد يرفض التحديث فوق توقيع مختلف («لم يُثبَّت التطبيق»). من
     1.1.0+5 فصاعداً التوقيع ثابت ⇒ التحديثات تُثبَّت فوق بعضها مباشرة.
   - إن رفض الهاتف التثبيت: افتح الإعدادات ← التطبيقات ← القائمة ⋮ ← «تثبيت
     تطبيقات غير معروفة» ← فعّله للمتصفح/مدير الملفات الذي حمّلت به.
2. الرابط مضبوط مسبقاً — يعمل فور الفتح. إن أردت قاعدة أخرى افتح ⚙️
   وألصق الرابط (`https://xxxx-default-rtdb.firebaseio.com`)؛ مفتاح
   المصادقة اختياري إذ تُنشئ اللوحة هويتها تلقائياً.
3. عندما يرسل العميل رسالة واتساب فيها «بصمة التفعيل» ألصقها في الحقل الأول،
   اختر الخطة والمدة، ثم [تفعيل وترقية الحساب].
4. يلمس العميل التفعيل فوراً عند ضغطه «تأكيد عملية الشراء» في تطبيقه —
   دون مسح بيانات أو إعادة تثبيت.
